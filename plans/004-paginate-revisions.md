## Design and implementation
1. Add mocked API tests first. Use request cursor made of validated ISO created_at and UUID id (JSON encoded as base64url or two query parameters is acceptable; choose one and document). Order by created_at descending then id descending for deterministic ties. Apply site filter plus lexicographic strictly older-than cursor. Validate cursor before query construction. Retrieve at most 21 rows (20 visible plus one older predecessor) with query limit. Return 20 display revisions plus nextCursor only if predecessor exists. Never send documents to browser. Initial version means no actual older row, not merely page boundary.
2. Compare each visible row to the immediately following row, including the extra predecessor. Resolve only visible authors concurrently with a bounded pool (e.g. four), preserving existing Former staff member fallback. Preserve private endpoint headers and membership checks.
3. Dashboard stores cursor and appends successive server pages. Refresh resets pagination and replaces results only after success. Show older revisions fetches the next page; hide when nextCursor absent, disable while loading, preserve current rows and cursor on append failure, allow retry. Guard duplicate/stale responses, including refresh racing an in-flight page request; maintain restore actions. Existing old mocked {revisions:[]} responses must be treated as an exhausted list.
